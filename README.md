**Соберите проверку безопасности как схему — от исходников до отчёта.**

Garden — веб-приложение для построения и запуска сценариев анализа безопасности. Соединяйте ноды в визуальном редакторе, проверяйте код и зависимости, разбирайте находки с AI и отправляйте результаты через webhook или почту.

Проект объединяет редактор workflow, собственные сканеры, историю запусков и двух помощников: **Скрепку** для разбора безопасности и **Архитектора** для сборки сценариев.

> Текущая версия — локальный прототип с рабочими сценариями для Kotlin/Gradle и учебным проектом Repair Desk. Область анализа и ограничения описаны ниже.

## Что уже работает

- **Визуальный редактор.** Создание схем из нод и соединений, настройка узлов, сохранение и редактирование workflow. Отмена изменений через `Ctrl+Z`, история до 100 состояний в текущем редакторе.
- **Проекты и загрузка исходников.** Встроенный учебный проект, создание своих проектов, загрузка отдельных файлов и ZIP-архивов.
- **Три направления анализа.** Поиск встроенных секретов, проверка зависимостей по локальному справочнику и статические проверки Kotlin-кода.
- **Управление потоком.** Объединение находок, устранение дублей по ID и условные ветви `true` / `false` по количеству результатов.
- **Наблюдение за запуском.** Состояния нод и обновления выполнения через Server-Sent Events, сохранение истории в SQLite.
- **Отчёты.** Находки с категорией, уровнем серьёзности, файлом, строкой, описанием и рекомендацией; JSON через API.
- **AI в рабочем процессе.** Разбор результатов, генерация схемы по текстовому запросу и изменение текущей сборки в диалоге.
- **Автоматизация.** Настройки расписаний, интеграция с HCL Domino, webhook и отправка отчётов через Gmail SMTP.
- **Вход в приложение.** Страница авторизации, сессионная cookie и выход из аккаунта.

## Из чего состоит workflow

| Нода | Назначение |
| --- | --- |
| `manual` | Ручной старт сценария |
| `schedule` | Запуск по расписанию: интервал, ежедневное время или cron |
| `repository` | Шаг работы с исходниками выбранного проекта |
| `secrets` | Поиск потенциальных секретов в коде и конфигурации |
| `sca` | Проверка Gradle-зависимостей по локальной базе уязвимостей |
| `sast` | Статические проверки Kotlin-кода |
| `merge` | Объединение результатов входящих ветвей |
| `if` | Ветвление по минимальному количеству находок |
| `ai` | AI-анализ поступивших находок |
| `webhook` | Отправка итогового отчёта во внешний HTTPS-сервис |

Встроенная схема **Full Security Audit**:

```text
Manual → Repository → Secrets → SCA → SAST → Merge
```

Её можно дополнить AI-анализом, условием и уведомлением. Проверки допускают и отдельные ветви с последующим объединением.

Перед сохранением и запуском сервер проверяет граф: уникальность ID, существование связанных нод, допустимость типов и ветвей, отсутствие циклов. Webhook должен завершать ветвь. В одном workflow допускается одна нода расписания; от неё должны быть достижимы все остальные ноды.

**Важно:** `repository` не клонирует удалённый Git-репозиторий. Сейчас исходники поступают из встроенного примера или загрузки пользователя.

## Быстрый старт

Нужны Python с поддержкой синтаксиса 3.10+ и браузер. Ниже — команды для Windows PowerShell, выполняемые из корня репозитория.

### 1. Установить зависимости

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Запустить сервер

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Backend обслуживает и API, и веб-интерфейс; отдельная сборка frontend не требуется.

При первом старте приложение создаёт `garden.sqlite3`, учебный проект и сценарий **Full Security Audit**.

### 3. Войти и выполнить первую проверку

1. Войдите через страницу авторизации.
2. Выберите учебный проект **Repair Desk**.
3. Откройте **Full Security Audit** и запустите сценарий.
4. Дождитесь завершения нод и откройте результаты.
5. Для своего кода создайте проект, загрузите исходники и привяжите к нему workflow.

**Авторизация в текущей версии:** проверка одной учётной записи задана в `valid_login()` в `app.py`. Самостоятельная регистрация и настройка аккаунтов через переменные окружения не реализованы. Данные для входа следует получить у владельца экземпляра; если вы разворачиваете собственную копию, адаптируйте эту функцию.

Базовые сканеры работают без LLM. Для AI-функций требуется отдельная настройка.

## AI-помощники

**Скрепка** помогает разобраться в находках и рекомендациях по безопасности. **Архитектор** получает контекст текущей схемы и диалога, отвечает на вопросы и может предложить обновлённый workflow, который интерфейс сохраняет. В приложении также есть генерация схемы по текстовому описанию и отдельная нода `ai`.

Предложенные AI схемы проходят серверную проверку структуры. Новые расписания при генерации создаются выключенными.

### OpenAI-совместимый API

Укажите параметры в той же PowerShell-сессии, из которой запускаете сервер:

```powershell
$env:LLM_BASE_URL = "https://api.openai.com/v1"
$env:LLM_API_KEY = "<ваш API-ключ>"
$env:LLM_MODEL = "<модель вашего провайдера>"

.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

`LLM_BASE_URL` — базовый адрес API, включая `/v1`, без `/chat/completions`. При использовании другого совместимого провайдера замените адрес и имя модели.

### Локальная модель через Ollama

После установки Ollama и Python-зависимостей:

```powershell
ollama pull qwen2.5:7b
.\start-local.ps1
```

Скрипт проверяет доступность Ollama, при необходимости запускает сервис и поднимает Garden с моделью `qwen2.5:7b`. Модель должна быть загружена заранее.

При использовании внешнего LLM API содержимое AI-запросов, включая переданный контекст и находки, уходит выбранному провайдеру.

## Что проверяют сканеры

| Направление | Реализованные проверки |
| --- | --- |
| Secrets | Подозрительные литералы паролей, API-ключей и токенов; некоторые fallback-секреты и токены, собираемые из констант |
| SCA | Координаты Gradle-зависимостей, версии из properties и переменных, учёт `gradle.lockfile`, сопоставление с диапазонами локального справочника |
| SAST | Отдельные шаблоны SQL-инъекций, динамического построения команд ОС, слабой криптографии, отключения TLS-проверки, небезопасного CORS и открытых чувствительных маршрутов |

Для SCA используется файл [`vulnerabilities.json`](git_org/training-main/vulnerability-database/vulnerabilities.json). Если совпадение найдено, результат содержит идентификатор advisory, диапазоны затронутых версий и исправленные версии из справочника.

### Границы анализа

- SAST основан на шаблонах и ориентирован на Kotlin. Полноценного анализа AST и потоков данных нет.
- SCA ограничен реализованным разбором Gradle и содержимым локальной базы; автоматическое обновление глобальной базы CVE не реализовано.
- Поддержка загрузки формата файла не означает наличие полноценного сканера для его языка.
- Совпадения требуют проверки человеком; отсутствие находок не гарантирует безопасность проекта.
- Исходники не собираются и не запускаются в ходе этих проверок.

### Ограничения загрузки

| Ограничение | Значение |
| --- | --- |
| Размер запроса загрузки | До 10 МБ |
| Размер отдельного файла | До 1 МБ |
| Суммарный размер содержимого ZIP | До 30 МБ после распаковки |
| Число элементов ZIP | До 1000 |
| Кодировка исходников | UTF-8, включая UTF-8 с BOM |

Загрузчик принимает Kotlin/Gradle-файлы, конфигурации и ряд текстовых форматов: `.kt`, `.kts`, `.gradle`, `.yaml`, `.yml`, `.properties`, `.toml`, `.lockfile`, `.json`, `.xml`, `.env`, `.sql`.

Пути с выходом за пределы проекта, символические ссылки, специальные файлы и дубли путей в архиве отклоняются. Служебные каталоги вроде `.git`, `node_modules` и `.venv` загружать нельзя.

## Расписания и уведомления

### HCL Domino

В ноде `schedule` доступны интервал в минутах, ежедневное время и cron с часовым поясом IANA. Исполнение расписаний интегрировано с внешним агентом Domino: один запущенный Uvicorn сам по себе не заменяет настроенный агент.

Инструкция развёртывания и исходники агентов находятся в [`integrations/domino`](integrations/domino/SETUP.txt):

- `SchedulerTick.lss` — обработка расписаний;
- `SendReports.lss` — отправка отчётов;
- `GardenConnectionTest.lss` — проверка соединения;
- `setup-token.ps1` — настройка токена интеграции.

API интеграции требует Bearer-токен длиной не менее 32 символов. Его можно задать через `GARDEN_DOMINO_TOKEN` или файл, путь к которому указан в `GARDEN_DOMINO_TOKEN_FILE`.

### Webhook

Конечная нода `webhook` отправляет отчёт и сохраняет результат доставки. Для хранения защищённых настроек нужен ключ Fernet в `GARDEN_WEBHOOK_KEY` вне базы данных.

Сгенерировать ключ и задать его для текущей сессии:

```powershell
$env:GARDEN_WEBHOOK_KEY = & .\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Сохраните этот ключ в защищённом месте и используйте тот же при следующих запусках: новый ключ не расшифрует прежние настройки.

### Gmail SMTP

Для прямой отправки отчётов используются:

```powershell
$env:GARDEN_GMAIL_SENDER = "<адрес отправителя>"
$env:GARDEN_GMAIL_RECIPIENT = "<адрес получателя>"
$env:GARDEN_GMAIL_PASSWORD = "<пароль приложения Gmail>"
```

Задайте значения до запуска backend. Адреса лучше указывать явно: текущий модуль содержит значения по умолчанию для конкретного экземпляра. Пароли и токены не следует добавлять в репозиторий.

## Структура проекта

```text
app.py                         API, авторизация, проекты и исполнение workflow
backend/
  scanners.py                  Secrets, SCA и SAST
  ai_helper.py                 Подключение LLM и контекст помощников
  scheduling.py                Расписания и API интеграции Domino
  notifications.py             Webhook и защита его настроек
  gmail.py                     Отправка отчётов через Gmail SMTP
frontend/
  index.html                   Основной интерфейс и редактор
  login.html                   Страница входа
  helper.js                    Интерфейс помощника
3d/                            Модели и ресурсы персонажей
integrations/domino/           Агенты Domino и инструкция подключения
git_org/training-main/         Учебный проект и база уязвимостей
tests/                         Тесты расписаний, webhook и почты
requirements.txt               Python-зависимости
start-*.ps1                    Скрипты запуска и интеграций
```

Данные приложения, загруженные исходники, workflow и история сохраняются локально в SQLite. Сессии входа хранятся в памяти процесса и сбрасываются при перезапуске backend.

## API

Обычные API-маршруты требуют авторизованной сессии. Маршруты `/api/domino/*` используют отдельный Bearer-токен.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/projects` | Список проектов |
| `POST /api/projects` | Создание проекта |
| `POST /api/projects/upload` | Загрузка исходников: `project_id` и `filename` в query, содержимое в теле запроса |
| `GET /api/nodes` | Поддерживаемые типы нод |
| `GET /api/workflows` | Сохранённые workflow |
| `POST /api/workflows` | Создание workflow |
| `PUT /api/workflows/{id}` | Обновление workflow |
| `POST /api/workflows/generate` | Генерация схемы по описанию |
| `POST /api/workflows/assistant` | Диалог с Архитектором |
| `POST /api/workflows/{id}/run` | Запуск проверки |
| `GET /api/runs` | История запусков |
| `GET /api/runs/{id}/events` | Поток событий выполнения, SSE |
| `GET /api/runs/{id}/report` | JSON с находками |
| `POST /api/assistant` | Запрос к помощнику по безопасности |
| `POST /api/notifications/test` | Проверка уведомления |

## Проверки для разработки

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

Существующие тесты покрывают расписания, уведомления и Gmail. Они не заменяют проверку визуального редактора в браузере.

## Текущий статус

Garden уже позволяет пройти полный локальный сценарий: **выбрать исходники → собрать проверку → запустить → разобрать находки → отправить отчёт**.

Версия рассчитана на локальную работу и демонстрацию. Перед публичным развёртыванием потребуется адаптация авторизации и эксплуатации; текущий запуск по умолчанию привязан к `127.0.0.1`.
